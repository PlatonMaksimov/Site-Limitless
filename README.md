# Limitless

Русскоязычный сайт на vanilla HTML/CSS/JS, без внешних зависимостей.
Требуется Node.js 22 или новее и npm. Устанавливать пакеты не нужно.

## Команды

```sh
npm run dev
npm test
npm run build
```

`npm run dev` (или `npm start`) запускает локальный сервер на
http://127.0.0.1:4173. Сервер привязан к loopback, не предназначен для
публичного размещения и не обрабатывает заявки.

Если порт занят: `npm run dev -- --port 4180`.
Откройте `http://127.0.0.1:4180`.

`npm test` запускает встроенный тестовый раннер Node.js. Тесты создают
изолированные временные проекты и не меняют файлы интерфейса.

`npm run build` копирует `index.html`, `src/` и содержимое `public/` в
`dist/`. Например, `public/images/photo.webp` становится
`dist/images/photo.webp` и доступен по `/images/photo.webp`.
Каталог `public/` необязателен; `index.html` и `src/` обязательны.
Сборка не минифицирует код, не удаляет каталоги или посторонние файлы.
Совпадающие файлы предыдущей сборки обновляются; устаревшие файлы остаются.
Для публикации используйте проверенный чистый каталог, не переносите туда
секреты или посторонние файлы. Конфликты исходных путей и символические
ссылки приводят к ошибке, а не к записи за пределами `dist/`.

## Структура

```text
index.html            — разметка страницы
src/site-data.js       — коммерческие данные, контакты, кейсы и конфигурация
src/app.js             — UI и поведение страницы
src/lead.js            — интеграция формы заявки
public/                — статические ресурсы, доступные от корня сайта
scripts/serve.mjs      — локальный статический сервер
scripts/build.mjs      — сборка без зависимостей
test/tooling.test.mjs  — проверки сервера и сборки
tests/lead.test.mjs    — проверки валидации и отправки
scripts/browser-check.mjs — необязательная проверка в браузере
dist/                  — результат сборки
```

Сервер отдаёт только `index.html`, файлы `src/` и содержимое `public/`.
Не кладите секреты в эти файлы. Скрытые пути, traversal и выход через
символические ссылки за разрешённые каталоги заблокированы; листинга
каталогов и подмены неизвестных адресов главной страницей нет.

Браузерная проверка запускается отдельно через `node scripts/browser-check.mjs`.
Требуется уже установленный Playwright. Если он не находится в проекте,
задайте `PLAYWRIGHT_MODULE` (полный путь к `playwright/index.mjs`) и при
необходимости `BROWSER_EXECUTABLE` (путь к Chrome/Edge). Проверка использует
свободный loopback-порт, ничего не отправляет внешним сервисам и сохраняет
скриншоты и отчёт в `artifacts/`. Успех и ошибка отправки проверяются
на подменённых тестовых ответах, а не на реальной доставке.

## Контракт заявки

- `config.form.endpoint` — адрес обработчика. Пустая строка означает
  **деморежим**: сетевой отправки нет; интерфейс не должен сообщать о
  доставленной заявке.
- `config.privacyUrl` — ссылка на юридический документ. Пустая строка
  означает, что документа нет: **реальная отправка заблокирована**,
  даже если endpoint указан. Для запуска нужны действительный документ
  и явное согласие пользователя.
- Endpoint должен быть **same-origin**: тот же протокол, хост и порт,
  что у сайта. Предпочтителен относительный путь, например `/api/leads`.
  Нельзя отправлять данные на внешний адрес или через редирект на него.
- Запрос: `POST`, `Content-Type: application/json`, тело:

```json
{
  "name": "Анна",
  "contact": "anna@example.com",
  "service": "website",
  "message": "Описание задачи",
  "consent": true
}
```

Значения `service`: `website`, `ads`, `both`, `unsure`.

## Что заменить перед публикацией

- `src/site-data.js`: `config.name`, `email`, `phone`, `telegramUrl`,
  `privacyUrl`, `form.endpoint`. Отсутствующие контакты не показываются.
- Там же: массив `projects` с задачами и решениями. Пока все три проекта
  явно обозначены как демонстрационные концепции. Их превью собраны в
  функции `projectPreview` файла `src/app.js`; при добавлении реальных
  работ замените также превью и пояснение под ними в `index.html`.
- `config.commercial` резервирует место для подтверждённых цен и сроков.
  Сейчас никаких неподтверждённых сумм или сроков сайт не публикует.
- `index.html`: SEO-description, Open Graph и Twitter-метаданные.
  При переименовании обновите их вместе с `config.name`.
- `public/favicon.svg`: значок сайта. Внешние шрифты, трекеры и изображения
  не загружаются; графика интерфейса выполнена средствами CSS/SVG.

Сначала настройте backend и предоставленный юридический документ,
затем проверьте заявку на тестовом окружении. Не ставьте фиктивную
ссылку на документ только ради включения отправки.

Успех подтверждается только сочетанием **HTTP 2xx** и корректного
**JSON `{"ok": true}`**. Один успешный HTTP-статус, пустое тело, HTML
или `{"ok": false}` не являются подтверждением. При ошибке нельзя
показывать успешную доставку; введённые данные следует сохранить для
повторной попытки.

Обработчик реализуется отдельно на сервере. Он обязан:

1. Валидировать типы, обязательные поля, допустимую услугу, длины полей,
   максимальный размер тела запроса и строгое `consent === true`.
   Проверка в браузере не заменяет серверную.
2. Ограничивать частоту запросов (rate limit), проверять допустимый
   источник запросов и защищаться от злоупотреблений.
3. Держать ключи почты, CRM, ботов и другие секреты исключительно
   **server-side**. Не помещать их в `src/`, `public/`, HTML или сборку.
4. Возвращать `{ "ok": true }` только после фактического принятия
   заявки серверной системой; ошибки возвращать без секретов и
   персональных данных в диагностике.

Статический сервер из этого проекта отвечает на `POST` статусом 405.
Для реальной отправки нужен отдельный backend за тем же origin
(например, через reverse proxy); одной статической публикации недостаточно.
